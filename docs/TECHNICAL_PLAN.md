# Technical plan

## Status
The original event-registry idea was replaced before implementation: Diana testnet rejects uploads of user CosmWasm code, and current QoreX EVM support is read-only. ProofStamp uses a supported native-lane `MsgSend` with a short digest memo, signed and broadcast by QoreX.

## Architecture
- React/Vite app generated by `create-qorechain-dapp@0.14.0 --template fullstack-web`.
- QoreX native provider from `@qorechain/qorex-types` 0.1.0; use `signAndBroadcast` on `qorechain-diana`.
- Browser Web Crypto computes a SHA-256 digest over the selected file. File bytes and filename are never sent to the server or chain.
- Submit a 1 uqor `MsgSend` from the connected address to itself with a versioned memo `QPROOF/1:<sha256-hex>`. QoreX shows the fee and signs/broadcasts with its hybrid pipeline.
- Fetch the transaction through `/lcd/cosmos/tx/v1beta1/txs/{hash}`. Confirm network identity from `/lcd/cosmos/base/tendermint/v1beta1/node_info`; inspect result code, tx hash, memo, self-send, hybrid extension signature length, and `pqc_hybrid_verify` status.
- Configure `/lcd` as a Vite dev proxy and a Vercel rewrite to the public Diana REST endpoint, avoiding direct browser requests to the no-CORS API.

## Risks and limits
- Public-chain memo and wallet address are durable and visible. SHA-256 is a fingerprint, not encryption; anyone with the file can compute the same digest.
- The receipt proves only that an address submitted the digest by the included block. It does not prove file authorship, truth, or prior existence.
- QoreX may report a transaction submitted before the REST index exposes it. Poll a bounded number of times, then show pending and let users retry verification.
- Never display a locally computed digest or wallet return value as on-chain proof until an independent fresh REST read confirms it.

## Stages
1. Build local hashing, QoreX connect, wallet approval, transaction states and proof receipt.
2. Implement and validate chain readback, including the hybrid signature extension and validator verdict.
3. Verify Vercel proxy/build setup, then conduct one real Diana wallet run and record the actual transaction evidence.

## Security and privacy
- Testnet only; no real funds or production credentials.
- Never handle private keys or seed phrases.
- Keep file processing in the browser; limit chain memo to the digest and fixed protocol prefix.
- Validate chain ID, hash, message and proof before labeling any receipt verified.
- Fail closed if RPC data is missing or inconsistent.
